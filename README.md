# Hyper Duel — native recompilation

A native Windows/Linux port of **Hyper Duel (Japan)** for the Sega Saturn, built with
[satrecomp](https://github.com/tmcleroy/satrecomp) 0.2.0. The Saturn's two SH-2 programs are
translated to C++ ahead of time and run on satrecomp's own machine; no emulator and no BIOS image
is part of the port. The player supplies their own disc image.

This project is not affiliated with or endorsed by Sega or Technosoft. No game data, disc image,
BIOS, save, generated translated code or recording is distributed here.

## Disc

The port expects an unmodified **Hyper Duel (Japan)** Saturn disc:

| Header field | Value |
| --- | --- |
| Product number | `T-1809G` |
| Version | `V1.001` |
| Release date | `19961002` |
| Area | `J` |
| Data track | track 1, MODE1/2352 |

The launcher checks these values from the first sector of the data track. A different release may
boot but is not the validated target.

## Build (Windows 11 x64)

Toolchain used and tested by this project (matching satrecomp's Windows CI):

- MSYS2, `MINGW64` environment
- `mingw-w64-x86_64-gcc`, `mingw-w64-x86_64-cmake`, `mingw-w64-x86_64-ninja`,
  `mingw-w64-x86_64-python`, `mingw-w64-x86_64-sdl3`, `mingw-w64-x86_64-zlib`, `make`

From an MSYS2 MINGW64 shell at the project root:

```sh
make            # translated code (if any) + port
make launcher   # launcher beside the port
```

Build output:

- `build/hyperduel/hyperduel.exe` — the port
- `build/hyperduel/hyperduel-launcher.exe` — the launcher

Portable Windows package:

```sh
tools/package_windows.sh
# dist/Hyper-Duel-Windows-x64/
```

## Linux x86_64 / Steam Deck

The release AppImage is built on Ubuntu 22.04 (glibc 2.35) with GCC 11 and a static
SDL 3.4.16, which is older than current SteamOS. On a Linux x86_64 host with the
project's development packages, a static SDL3 install, and `appimagetool`:

```sh
export CMAKE_PREFIX_PATH=/path/to/sdl3-static
APPIMAGETOOL=/path/to/appimagetool tools/package_appimage.sh
# dist/Hyper-Duel-v0.1.0-SteamDeck-x86_64.AppImage
```

The AppImage carries the runtime, launcher, its original icon, licenses and the C++
runtime; it does not carry glibc, graphics drivers, X11/Wayland/audio system libraries,
or any game data. SteamOS's system libraries and Mesa drivers are used. `make app` is
the toolkit's macOS bundle target in satrecomp 0.2.0, not an AppImage target.

For Desktop Mode, make the AppImage executable and run it, or add it to Steam. For
Gaming Mode, add it as a non-Steam game in Desktop Mode, then launch it from the Deck;
the launcher opens full screen when it detects gamescope/Steam Game Mode. Controller
bindings use SDL3 gamepads. The project owner confirmed the AppImage on Steam Deck
(Desktop and Gaming Mode, sound through gameplay); full-stage testing is still a
separate, longer check.

The first build is interpreter-only. Translated code is generated later from a block
recording; the current recorded paths are fully translated. Generated code is large
and takes about 13 minutes to compile on this machine.

## Run

The launcher stores the chosen disc, saves and settings under the game's home folder
(`HYPERDUEL_HOME`, otherwise the platform's normal application-data folder). Choose the `.cue`
file once, then Play.

For a direct run (from the project root, with a developer-local `local.mk` defining `DISC`):

```sh
make run
```

or explicitly:

```sh
build/hyperduel/hyperduel.exe \
  --disc "C:/path/to/Hyper Duel (Japan).cue" \
  --backup work/hyperduel/backup.bin \
  --settings work/hyperduel/settings.ini
```

Headless deterministic run:

```sh
build/hyperduel/hyperduel.exe --disc "C:/path/to/game.cue" --headless --frames 600 \
  --backup work/hyperduel/backup.bin --hash-log work/hyperduel/boot.hashes
```

## Saves, settings and logs

- Saves: `saves/backup.bin` in the launcher's game folder (or the `--backup` path).
- Settings: `settings.ini` in the launcher's game folder (or `--settings` path).
- Per-run logs and generated files: `work/hyperduel/` (git-ignored).
- Build output: `build/hyperduel/` (git-ignored).

## Controls and modes

Keyboard: arrows move; Return is Start; Z/X/C are A/B/C; A/S/D are X/Y/Z; Q/E are L/R.
A gamepad's lower face buttons are A/B/C, and Start is Start. Change them on the
launcher's Controllers page.

At the title screen:

- **Start** starts Arcade mode.
- **Hold Down and press Start** opens the mode menu (`SATURN MODE`, `ARCADE MODE`,
  `OPTION`).

Start pauses during play. A/B are the Fighter/Armor buttons; pressing both is the
special attack.

## Audio

Arcade mode's music and effects are generated by the SCSP/68000 sound driver. Saturn
mode's music is CD-DA; the port reads the audio sectors from the player's own disc and
plays them at the SCSP's 44.1 kHz rate, independently of the data-sector FIFO. Pause,
resume, stop, finite/infinite repeat and track changes are handled. Do not use a
pre-fix save state: the music range fields changed.
